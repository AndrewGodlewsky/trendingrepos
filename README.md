# GitHub Trending Repos Pipeline

A daily-automated Python pipeline that fetches trending GitHub repositories, scores them by multiple trending signals, generates AI summaries via Claude, and publishes a dark-themed static website to `docs/` (GitHub Pages / Cloudflare Pages compatible).

## Project Overview

This pipeline runs daily and produces a searchable, filterable website showing the most trending GitHub repositories. It is self-contained: no Node.js, no build tools, no external CSS frameworks. The entire website is a single `docs/index.html` file generated by Python.

Key capabilities:

- Fetches repos pushed in the last 30 days with at least 50 stars via the GitHub Search API
- Ranks them using a composite score: star velocity, fork ratio, watcher ratio, recency, issue health
- Summarizes each repo in 2-4 sentences using Claude AI (Haiku by default for cost efficiency)
- Generates a dark-themed, fully client-side-searchable static site
- Stores all data as plain JSON (no database required)
- Rotates daily snapshots to compute star deltas (stars gained since the previous run)

---

## How It Works

The pipeline runs six sequential steps:

| Step | Module | What it does |
|------|--------|--------------|
| 1. FETCH | `fetcher.py` + `github_client.py` | Calls GitHub Search API, streams up to 1,000 raw repo dicts |
| 2. RANK | `ranker.py` | Deduplicates, scores, sorts, caps to TOP_N_REPOS |
| 3. PERSIST | `storage.py` | Rotates snapshots, writes `data/repos.json` |
| 4. SUMMARIZE | `summarizer.py` | Sends each repo's README + metadata to Claude, writes `data/summaries.json` |
| 5. GENERATE | `site_generator.py` | Merges data, writes `docs/index.html` + `docs/data.json` |
| 6. SCHEDULE | `run_pipeline.py` | Entry point chaining all steps; invoked by Task Scheduler |

## Prerequisites

- **Python 3.9 or later** (developed and tested on Python 3.14)
  - Verify: `python --version`
- **GitHub Personal Access Token (PAT)**
  - Go to GitHub Settings > Developer settings > Personal access tokens > Tokens (classic)
  - Grant the `public_repo` scope (read-only access to public repositories is sufficient)
  - The free tier gives 5,000 Search API requests per hour — more than enough for this pipeline
- **Anthropic API Key**
  - Sign up at [console.anthropic.com](https://console.anthropic.com)
  - Generate an API key from the API Keys section
  - Claude Haiku (the default model) costs approximately $0.25 per million input tokens

## Configuration

All configuration is done via environment variables. Copy `.env.example` to `.env` and edit it.

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `GITHUB_PAT` | Yes | — | GitHub Personal Access Token. Used for authenticated Search API calls (5,000 req/hr vs 60/hr unauthenticated). |
| `ANTHROPIC_API_KEY` | Yes | — | Anthropic API key for Claude summarization. |
| `FETCH_MIN_STARS` | No | `50` | Minimum star count for repos included in the fetch query. Increase to reduce noise (e.g. `200`). |
| `FETCH_DAYS_BACK` | No | `30` | How many days back to look for recently-pushed repos. |
| `TOP_N_REPOS` | No | `200` | Maximum repos to keep after ranking. Summarizing 200 repos takes roughly 5-10 minutes and costs ~$0.05 with Haiku. |
| `SUMMARIZE_MODEL` | No | `haiku` | Claude model: `haiku` (fast, cheap) or `sonnet` (more detailed, ~5x more expensive). |
| `LOG_LEVEL` | No | `INFO` | Python logging level: `DEBUG`, `INFO`, `WARNING`, `ERROR`. |
| `SITE_TITLE` | No | `GitHub Trending` | The H1 title displayed in the website header. |

Example `.env`:

```
GITHUB_PAT=github_pat_11ABCDE_abc123
ANTHROPIC_API_KEY=sk-ant-api03-abc123
FETCH_MIN_STARS=100
TOP_N_REPOS=100
SITE_TITLE=My GitHub Trending
```

## Running Manually

Run the full pipeline from the project folder:

```
python run_pipeline.py
```

Skip expensive API steps during development:

```
# Re-generate the website from existing data (no API calls)
python run_pipeline.py --skip-fetch --skip-summarize

# Re-summarize and regenerate site (no GitHub fetch)
python run_pipeline.py --skip-fetch

# Fetch and regenerate site (no new summaries)
python run_pipeline.py --skip-summarize
```

Logs are written to `logs/run_YYYY-MM-DD.log` and also printed to stdout.

Run the tests:

```
pytest tests/
```

## Windows Task Scheduler Setup

The pipeline is designed to run daily via Windows Task Scheduler. Two methods are provided.

### Method A: Import the XML file (recommended)

1. Open a Command Prompt as Administrator.

2. Import the task XML:

   ```
   schtasks /create /xml "A:\Claude\workflow test\github-trending-task.xml" /tn "GitHub Trending Repos Pipeline"
   ```

3. If you want the task to run whether or not you are logged on, re-open Task Scheduler
   (search for "Task Scheduler" in Start), find the task under Task Scheduler Library,
   right-click > Properties > General tab > select "Run whether user is logged on or not",
   enter your password, and click OK.

4. Verify the task was created:

   ```
   schtasks /query /tn "GitHub Trending Repos Pipeline"
   ```

5. Test it immediately:

   ```
   schtasks /run /tn "GitHub Trending Repos Pipeline"
   ```

6. Check the log after a minute:

   ```
   type "A:\Claude\workflow test\logs\run_YYYY-MM-DD.log"
   ```

### Method B: Manual setup in Task Scheduler GUI

1. Open Task Scheduler (search in Start menu).
2. Click "Create Task" in the right panel.
3. **General tab**
   - Name: `GitHub Trending Repos Pipeline`
   - Select "Run whether user is logged on or not"
   - Check "Run with highest privileges"
4. **Triggers tab** > New
   - Begin the task: On a schedule
   - Daily, start at 6:00 AM
   - Click OK
5. **Actions tab** > New
   - Action: Start a program
   - Program: `C:\Users\godle\AppData\Local\Python\pythoncore-3.14-64\python.exe`
     (adjust to your Python path — run `where python` to find it)
   - Arguments: `"A:\Claude\workflow test\run_pipeline.py"`
   - Start in: `A:\Claude\workflow test`
6. **Conditions tab**
   - Uncheck "Start the task only if the computer is on AC power"
   - Check "Start only if the following network connection is available"
7. **Settings tab**
   - Check "Run task as soon as possible after a scheduled start is missed"
   - Set "Stop the task if it runs longer than: 1 hour"
   - Check "If the task fails, restart every: 5 minutes" up to 3 times
8. Click OK, enter your password if prompted.

### Updating the Python Path

If your Python executable is not at the default path, find the correct one:

```
where python
```

Then update the `<Command>` element in `github-trending-task.xml` or the Action in the GUI.

## Deploying to GitHub Pages

GitHub Pages serves the `docs/` folder directly. After each pipeline run, commit and push the updated `docs/index.html`.

### One-time setup

1. Push your project to a GitHub repository.

2. In your GitHub repository, go to **Settings > Pages**.

3. Under "Build and deployment", select **Source: Deploy from a branch**.

4. Set branch to `main` (or your default branch) and folder to `/docs`.

5. Click Save. GitHub will show you the URL, e.g. `https://yourusername.github.io/repo-name/`.

### Daily update workflow

After the pipeline runs and writes `docs/index.html`, commit and push:

```
git add docs/index.html
git commit -m "chore: update trending repos $(date /t)"
git push
```

To automate this as part of the pipeline, add these lines to the end of `run_pipeline.py`
(before the "Done" section), or create a separate `deploy.bat` script:

```bat
@echo off
cd /d "A:\Claude\workflow test"
git add docs/index.html
git commit -m "chore: daily trending update"
git push
```

Schedule `deploy.bat` as a second Task Scheduler task running 15 minutes after the pipeline.

## Deploying to Cloudflare Pages

Cloudflare Pages can build and serve your `docs/` folder automatically on every push.

### One-time setup

1. Log in to [dash.cloudflare.com](https://dash.cloudflare.com) and go to **Workers & Pages**.

2. Click **Create application > Pages > Connect to Git**.

3. Select your GitHub repository and authorize Cloudflare.

4. Configure the build settings:
   - **Framework preset**: None
   - **Build command**: (leave empty — no build step needed)
   - **Build output directory**: `docs`

5. Click **Save and Deploy**. Cloudflare will deploy your site and give you a URL like
   `https://your-project.pages.dev`.

6. On every `git push`, Cloudflare automatically redeploys the updated `docs/index.html`.

### Custom domain (optional)

In the Pages project, go to **Custom domains > Set up a custom domain** and follow the
DNS configuration instructions.

## Troubleshooting

### "Missing required environment variables: GITHUB_PAT"

Your `.env` file is missing or the variable name is wrong. Double-check:

1. The file is named exactly `.env` (not `.env.txt` or `env.txt`).
2. The variable is `GITHUB_PAT=your_token_here` with no spaces around `=`.
3. The `.env` file is in `A:\Claude\workflow test\` (same directory as `run_pipeline.py`).

### "GitHub authentication failed"

Your PAT may be expired or have insufficient scopes.

1. Go to GitHub > Settings > Developer settings > Personal access tokens.
2. Check the token's expiry date and scopes (`public_repo` is required).
3. Regenerate if needed and update your `.env`.

### Pipeline fetches 0 repos

- Increase `FETCH_DAYS_BACK` (try `60` or `90`).
- Decrease `FETCH_MIN_STARS` (try `10`).
- Check your internet connection.
- Check `logs/run_YYYY-MM-DD.log` for the exact error message.

### Summarization is slow or times out

Claude Haiku is the fastest and cheapest model. If you are summarizing 200 repos for the
first time, expect 5-15 minutes. Subsequent runs only process new repos (existing summaries
are cached in `data/summaries.json`).

To reduce cost and time, lower `TOP_N_REPOS`:

```
TOP_N_REPOS=50
```

### Task Scheduler task does not run

1. Open Task Scheduler, find the task, and check "Last Run Result" in the list.
2. A result of `0x1` means the script exited with code 1 — check the log file.
3. A result of `0x41301` means the task is still running — it may be hung.
4. Make sure the Python path in the XML matches your actual Python location (`where python`).
5. Verify the working directory is set to `A:\Claude\workflow test`.

### docs/index.html is not updating on GitHub Pages

1. Confirm `docs/index.html` is committed and pushed (`git status`).
2. GitHub Pages can take 1-2 minutes to rebuild after a push.
3. Check the Pages build status in your repo under **Actions** (if using GitHub Actions) or
   **Settings > Pages**.

### Logs

All pipeline output is written to `logs/run_YYYY-MM-DD.log`. Set `LOG_LEVEL=DEBUG` in
your `.env` for verbose output that shows every API call, retry, and file write.
